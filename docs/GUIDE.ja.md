# Window FX: 手順

[English](GUIDE.md) · [Deutsch](GUIDE.de.md) · [Español](GUIDE.es.md) · [Français](GUIDE.fr.md) · [Italiano](GUIDE.it.md) · [Português](GUIDE.pt.md) · [Русский](GUIDE.ru.md) · **日本語** · [简体中文](GUIDE.zh_CN.md)

## 1. プラグインを入れる

プラグインレジストリから:

```sh
dms plugins install windowFx
```

または、リポジトリを DMS のプラグインフォルダーにクローンします。

```sh
git clone https://github.com/satoshoe-dev/dms-window-fx ~/.config/DankMaterialShell/plugins/WindowFx
```

## 2. 有効にする

設定 → プラグイン を開きます。一覧に Window FX が出てきます。オンにしてください。

![プラグイン一覧の Window FX](images/01-plugin-list.png)

出てこないときは、そのページの「スキャン」を押すか、`dms restart` でシェルを再起動します。

## 3. プラグインのファイルを niri に読ませる

プラグインはアニメーションを `~/.config/niri/windowfx.kdl` に書き込みます。niri がこのファイルを読むのは、設定がそれを include しているときだけです。次の行を `~/.config/niri/config.kdl` のいちばん最後に足してください。

```kdl
include optional=true "windowfx.kdl"
```

最後に置くのは、include がそれより前の内容を上書きするからです。設定に `window-close` や `window-open` を含む `animations` ブロックがあっても、プラグインの値が優先されます。`optional=true` があれば、ファイルがまだなくても niri は困りません。これには niri 26.04 以降が必要です。

niri はファイルを保存するとすぐに変更を読み込みます。

## 4. 閉じるときのアニメーションを選ぶ

プラグイン一覧で Window FX を開きます。「閉じるときのアニメーション」で 13 の種類から一つ選びます。たとえば「砕ける」です。

![種類の一覧が開いた設定ページ](images/02-close-animation.png)

端末を開いて、また閉じてみてください。ウィンドウが破片に割れ、回りながら枠の外へ落ちていきます。

![破片に割れていくウィンドウ](images/03-shatter.png)

「長さ」はかかる時間で、150 から 3000 ms まで選べます。600 ms なら素早く、1500 ms ならじっくり見られます。

## 5. ウィンドウの開き方を選ぶ

「開くときのアニメーション」の初期値は「閉じるときと同じ、逆再生」です。新しいウィンドウは、直前のウィンドウが消えたのと同じ動きを逆にたどって現れます。燃えさしが集まり、破片が舞い上がってつながります。閉じるときのアニメーションが「niri の標準」のあいだは、開くときも niri に任せます。

開くときには別の種類や「ランダム」も選べます。新しいウィンドウには niri 自身のアニメーションを使いたいなら「niri の標準」を選びます。「開くときの長さ」は閉じるときと同じように働きます。新しいウィンドウは早く出てきてほしいので、初期値は 450 ms です。

## 6. 光るふち

「光るふち」は、炎の境目、破片のあいだの割れ目、タイルの継ぎ目をアクセントカラーで光らせます。光のない落ち着いたアニメーションにしたいときはオフにします。

![アクセントカラーで光る割れ目](images/04-glow.png)

色は DMS のアクセントに従います。アクセントが変わると、次のアニメーションから新しい色で光ります。ブラウン管オフはいつも白く光ります。

## 7. 偶然に任せる (任意)

閉じるときのアニメーションに「ランダム」を選びます。するとウィンドウごとに種類が決まります。設定の下に「ランダムはこの中から選びます:」という一覧が出るので、種類ごとにオンとオフを切り替えます。

![ランダムの候補選び](images/05-random.png)

最初にオンになっているのは、燃えさし、砕ける、溶ける、グリッチ、ブラウン管オフ、コードの雨の 6 つです。全部オフにすると燃えさしが使われます。

## 8. 隣のウィンドウを待たせる (hold-layout のある niri)

列の途中のウィンドウが閉じると、niri はその右にあるウィンドウをすぐに空いた場所へ動かし、まだ続いているアニメーションの下へ滑り込ませてしまいます。使っている niri がオプション `hold-layout` を知っていれば、設定ページに「隣のウィンドウを待たせる」のスイッチが出ます。オンにすると、隣のウィンドウは閉じるアニメーションが終わるまでその場にとどまり、そのあとで詰めてきます。

`hold-layout` は niri 本体のオプションではなく、非公式のパッチによるものです。そのため、ディストリビューションの niri ではスイッチは表示されません。このガイドのほかの内容は、それがなくても使えます。

右に別のウィンドウがあるウィンドウで試してください。列の最後のウィンドウが閉じたときは、何も詰めてきません。

スイッチが出ないときは、その niri にはこのオプションがありません。プラグインは起動時に、オプションを使った小さなファイルを `niri validate` に読ませて確かめます。受け付けない niri には、このオプションを決して書きません。

## 9. アニメーションをプロファイルごとに持つ (任意)

[Profiles](https://github.com/satoshoe-dev/dms-profiles) プラグインを使っているなら、「プロファイルと一緒に保存するプラグイン」に `windowFx` を入力します。プロファイルごとにアニメーションを持てるので、仕事用には落ち着いたもの、夜はグリッチ、といった使い分けができます。

## 10. スクリプトから

```sh
dms ipc call windowFx kind melt      # close animation: a kind, random or default
dms ipc call windowFx open random    # open animation: mirror, a kind, random or default
dms ipc call windowFx status
```

種類の名前は `ember`、`dissolve`、`pixel`、`shatter`、`melt`、`glitch`、`crt`、`snow`、`scan`、`code`、`swirl`、`squares`、`blinds` です。

niri でキーに割り当てるには:

```kdl
binds {
    Mod+Shift+W hotkey-overlay-title="Window FX: random close animation" { spawn "dms" "ipc" "call" "windowFx" "kind" "random"; }
}
```

## 困ったとき

### ウィンドウの閉じ方が前と変わらない

手順 3 の include の行がないか、「閉じるときのアニメーション」が「niri の標準」になっています。プラグインがファイルを書いたかどうかは `ls ~/.config/niri/windowfx.kdl` でわかります。

### config.kdl に書いた自分のアニメーションが優先される

include の行が `animations` ブロックより上にあります。ファイルの最後に移してください。

### niri が `hold-layout` についての設定エラーを出す

niri がこのオプションのないものに入れ替わり、ファイルには前のオプションが残っています。DMS が動き出すとプラグインがもう一度確かめ、オプションなしでファイルを書き直します。niri は自分で読み込み直します。

### 「隣のウィンドウを待たせる」が出てこない

入っている niri が `hold-layout` を知りません。知っている niri になれば、DMS を次に起動したときにスイッチが出ます。

### ランダムなのにいつも同じ種類になる

手順 7 の一覧でオンの種類が一つだけか、一つもありません。一つもないときは燃えさしが使われます。

### プラグインをオフにしてもアニメーションが残る

プラグインは `windowfx.kdl` をそのまま残します。オフにする前に両方のアニメーションを「niri の標準」にするか、ファイルを消してください。
