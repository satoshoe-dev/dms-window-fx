# Window FX

[English](README.md) · [Deutsch](README.de.md) · [Español](README.es.md) · [Français](README.fr.md) · [Italiano](README.it.md) · [Português](README.pt.md) · [Русский](README.ru.md) · **日本語** · [简体中文](README.zh_CN.md)

niri のウィンドウに、閉じるときと開くときの専用アニメーションを付ける [DankMaterialShell](https://github.com/AvengeMedia/DankMaterialShell) 用のプラグインです。ウィンドウは燃え尽きたり、破片になって砕けたり、溶けたり、グリッチを起こしたり、古いブラウン管のように消えたりします。ふちはアクセントカラーで光ります。

![Window FX](assets/screenshot.png)

画像つきの手順: [インストールと設定の手引き](docs/GUIDE.ja.md)。

## できること

niri は閉じるウィンドウや開くウィンドウを、カスタムシェーダーで描くことができます。プラグインはそのシェーダーを `~/.config/niri/windowfx.kdl` に書き込み、niri はファイルが変わるとすぐに自分で読み込み直します。新しい設定は、次に閉じるか開くウィンドウから効きます。

種類は 13 あります。

| 種類 | どうなるか |
|---|---|
| 燃えさし | ぎざぎざの境目に沿ってウィンドウが燃え尽きる |
| 崩れる | 粗い粒がばらばらの順に消えていく |
| ピクセル化 | ブロックが大きくなってから薄れる |
| 砕ける | ウィンドウが破片に割れ、回りながら落ちる |
| 溶ける | 細い列がそれぞれの速さで下へ滑り落ちる |
| グリッチ | 裂け目、ずれた色チャンネル、跳ねるブロックのあとで崩れる |
| ブラウン管オフ | 線に、それから点に縮み、明るく光る |
| 砂嵐 | 画面がノイズに埋もれ、粒ごとにばらけていく |
| スキャン | 光の帯が下へ走り、あとにふちのワイヤーフレームが残る |
| コードの雨 | 文字の列が流れ落ち、そのあとにはコードだけが残る |
| 渦巻き | ウィンドウが中心のまわりに巻き込まれる |
| タイル | タイルがばらばらの順に縮む |
| ブラインド | 横向きの羽根が閉じていく |

「ランダム」は、自分で決めた候補の中からウィンドウごとに種類を選び直します。閉じるときと開くときには、それぞれ別の長さがあります。開くときは種類を逆向きに再生します。初期設定では、新しいウィンドウは直前のウィンドウが消えたのと同じ動きを逆にたどって現れます。「niri の標準」を選ぶと、そのアニメーションは niri に任せます。

「光るふち」をオンにすると、ふち、割れ目、継ぎ目が DMS のアクセントカラーで光ります。アクセントが変わると、プラグインはファイルを書き直します。ブラウン管オフはこの設定に関係なく、いつも白く光ります。

[Profiles](https://github.com/satoshoe-dev/dms-profiles) プラグインを使っているなら、設定 → プラグイン → Profiles → プロファイルと一緒に保存するプラグイン に `windowFx` を入力してください。プロファイルごとにアニメーションを持てるようになります。

## 必要なもの

DankMaterialShell 1.6.1 以降と niri 26.04 以降。niri のバージョンは下の include の行のためです。`optional=true` は niri 26.04 から使えます。

プラグインは自分のファイルを書くだけです。niri がそれを読むのは、niri の設定がそのファイルを include しているときだけです。次の行を `~/.config/niri/config.kdl` の末尾に足してください。

```kdl
include optional=true "windowfx.kdl"
```

末尾に置くのは、include がそれより前の内容を上書きするからです。こうすると、プラグインのアニメーションがメインの設定より優先されます。

「隣のウィンドウを待たせる」には、さらに非公式のパッチを当てた niri が必要です (下の「隣のウィンドウを待たせる」の節を参照)。それ以外は普通の niri で動きます。

## インストール

プラグインレジストリから:

```sh
dms plugins install windowFx
dms ipc call plugins enable windowFx
```

DMS の 設定 → プラグイン → ブラウズ からも入手できます。リポジトリから直接入れる場合:

```sh
git clone https://github.com/satoshoe-dev/dms-window-fx ~/.config/DankMaterialShell/plugins/WindowFx
dms ipc call plugins enable windowFx
```

そのあと 設定 → プラグイン → Window FX で閉じるときのアニメーションを選びます。選ぶまでは niri 自身のアニメーションのままです。

## 設定

設定 → プラグイン → Window FX

| 設定 | 初期値 |
|---|---|
| 閉じるときのアニメーション | niri の標準 |
| 長さ | 600 ms |
| 隣のウィンドウを待たせる | オフ (`hold-layout` を知っている niri のときだけ) |
| 開くときのアニメーション | 閉じるときと同じ、逆再生 |
| 開くときの長さ | 450 ms |
| 光るふち | オン |
| ランダムはこの中から選びます | 燃えさし、砕ける、溶ける、グリッチ、ブラウン管オフ、コードの雨 |

どちらの長さも 150 から 3000 ms まで設定できます。

## IPC

```sh
dms ipc call windowFx kind shatter   # close animation: a kind, random or default
dms ipc call windowFx open mirror    # open animation: mirror, a kind, random or default
dms ipc call windowFx status
```

種類の名前は `ember`、`dissolve`、`pixel`、`shatter`、`melt`、`glitch`、`crt`、`snow`、`scan`、`code`、`swirl`、`squares`、`blinds` です。

次のウィンドウのためにさいころを振る niri のキー割り当て:

```kdl
binds {
    Mod+Shift+W { spawn "dms" "ipc" "call" "windowFx" "kind" "random"; }
}
```

## 隣のウィンドウを待たせる

ウィンドウが閉じると、niri はそれをすぐにレイアウトから外します。隣のウィンドウはすぐに空いた場所へ動き出し、アニメーションがまだ続いている閉じかけのウィンドウの上に重なります。短いフェードならほとんど目立ちませんが、燃えるふちや落ちていく破片だと、その大部分が隣のウィンドウに隠れます。

そのために、`window-close` にオプション `hold-layout` を足す小さなパッチを niri 向けに書きました。これがあると、ウィンドウを外したことで動き出すもの (隣のウィンドウの移動、ビューのスクロール、列の大きさの変化) は、閉じるアニメーションが終わってから始まります。このパッチは niri 本体には含まれておらず、ディストリビューションの niri はこのオプションを知りません。このパッチを当ててビルドした niri でなければ、「隣のウィンドウを待たせる」は何もしません。

プラグインは起動時に、入っている niri がこのオプションを知っているかを確かめます。オプションを使った小さなファイルを `niri validate` に読ませるやり方です。知っていれば設定ページに「隣のウィンドウを待たせる」のスイッチが出ます。知らなければスイッチは隠れたままで、プラグインはこのオプションを書きません。標準の niri はファイル全体を受け付けなくなるからです。

## オフにするとき

プラグインをオフにしても `windowfx.kdl` はそのまま残るので、最後のアニメーションが残ります。niri 自身のアニメーションに戻すには、先に両方のアニメーションを「niri の標準」にするか、ファイルを消してください。`optional=true` があれば、ファイルがなくても niri は困りません。
